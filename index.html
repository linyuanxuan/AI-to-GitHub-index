01 / FEATURES

它替你做的三件事

先搞清楚机器和环境，再产出内容，最后才动手推。顺序不能反。

◍

先探测，再动手

git 装在哪、提交身份是谁、远端指向哪里、要不要走代理，一次问清楚，缺失就报错而不是瞎猜。

⌘

零硬编码个人信息

代码里没有用户名、邮箱和仓库地址，全部来自 git config 或当场传参。换台机器照样跑。

◈

模板 + JSON 渲染

一个极简模板引擎，支持变量、列表块和条件块，改版式不用碰 Python。

↻

认证不卡死

强制关闭终端密码提示，认证失败立刻返回退出码 4 并给出三条可执行方案，不会挂在登录界面上。

⇄

代理自动回退

直连 github.com 失败时，扫描常见本地代理端口并逐个验证，验证通过才用于推送。

◇

dry-run 先演练

加 --dry-run 只打印将要执行的动作：不改文件、不建仓库、不提交、不推送。

02 / QUICKSTART

三步跑起来

把它当作一个可执行的流程，不是一个要背下来的规范。

1

放进 skills 目录

git clone https://github.com/linyuanxuan/AI-to-GitHub-index.git \ ~/.workbuddy/skills/github-showcase-publish

装成用户级 skill，所有项目都能调用；也可放项目内的 .workbuddy/skills/。

2

填配置并渲染

cp assets/site.example.json site.json # 只改 repo_url 就够，owner 和域名会自动推导 python scripts/render.py --template assets/readme.template.md \ --config site.json --out README.md --no-escape python scripts/render.py --template assets/landing.template.html \ --config site.json --out index.html

脚本会列出没赋值的变量名，补齐后重跑即可。

3

提交并推送

python scripts/publish.py --dir . \ --remote-url https://github.com/<owner>/<repo>.git \ --message "feat: README + 介绍页"

先加 --dry-run 演练一遍更稳。身份缺省时读本机 git config。

04 / LIMITS

先说清楚它做不到什么

边界写在这里，省得你试完才发现。

✕

不替你建远端仓库
创建 GitHub 仓库要走 API，需要你的 token。它只负责往已存在的仓库推。

✕

不替你登录
认证交给系统 git（Credential Manager / SSH key）。凭据不进任何文件，也不经过脚本。

✕

介绍页是静态的
只有 HTML/CSS/JS，没有后端。项目本身的功能得在本地跑。

✕

内容要人来审
特性、规格、限制这些事实来自读代码，但措辞和取舍仍需要你过一眼，它不会替你吹。
